# 原生后台适配 — Windows 微信 4.1.15.51

2026-10-19。使用现有普通账号，后台读取本机消息库；文字与文件通过自写原生模块进入客户端发送服务。不使用 CU、窗口自动化、剪贴板、网页版、额外扫码、降级或替换当前客户端。

## 实现与版本锁定

`native/native_text.cpp` 是本项目独立实现，基于当前已安装客户端的静态分析及限定目标实机验证。没有复制缺少许可的第三方 Hook 源码，没有分发微信 DLL、反汇编文件、账号数据或会话密钥。

支持的 Weixin.dll SHA-256：`6c48a66cee5b03cc951e8ea1877313c3c7b044049d2c5f451281f7eaeb537b73`。控制器同时检查实际载入模块入口字节和自编译适配 DLL 哈希；不匹配即拒绝。

原生请求经客户端自己的任务执行器进入受管理线程上下文；不能从任意远程线程直接调用服务定位器，因为它依赖客户端 TLS。文字使用客户端文字发送入口。文件构造本地文件发送源，将目标改为已验证的稳定会话 ID，再交给客户端消息管理器处理上传与发送。没有写入微信数据库制造消息。

`src/wechat_bridge/native.py` 负责账号绑定、加载自编译 DLL、传递有界 UTF-8 请求和读取结果。只在显式 `native_experimental` 模式启用。模块需要留在进程中，以免仍在运行的异步回调指向已卸载代码。超时或异常返回 unknown，不自动重发。

## 实机证据

通过认证 HTTP 接口向唯一白名单“测试群”分别提交一条文字和两个 134 字节文本附件（含中文无扩展名）。三次原生调用均正常退出，回执为 locally_observed；群聊监听分别匹配各自的来源记录。文件最终本机记录具有非零 server_id，以及非空附件标识、CDN 地址、加密字段和 MD5；公开摘要只保留字段是否存在，不披露值。

这些证据确认调用了文件上传发送链路并形成客户端记录，不能替代另一位成员的下载或阅读验收。未验证跨账号接收、大文件、其他类型附件、连续多日稳定性或其他微信版本。发送队列验收后暂停，监听继续。

## 维护边界

微信升级后必须重新分析 ABI、消息结构、线程约束和生命周期，并先做非发送探针，再在明确授权的隔离目标验收。禁止将旧版本裸偏移盲目用于新版本。UI 和网页版均不是失败回退路线。
